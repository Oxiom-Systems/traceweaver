Authoring rules

  1. Keep the summary explanatory and the statement normative; do not duplicate the obligation elsewhere.
  2. Use one requirement type and one primary obligation per record. Split compound behavior that has independent acceptance paths.
  3. Link source, decisions, trace, verification, validation, and lifecycle state. Never infer authority from proximity.
  4. Keep implementation and publication holds explicit until separately proven and accepted.
  5. Retain superseded IDs as linked tombstones; never reuse an allocated ID.
