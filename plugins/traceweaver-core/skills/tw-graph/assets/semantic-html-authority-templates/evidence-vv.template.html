LLM served-equivalence control

For CAND-TW-HTML-025 validation, every LLM raw run shall separately record requested provider, model, and reasoning effort plus an immutable served_model_attestation_ref that resolves through the accepted central model-routing attestation interface. The accepted result shall bind the raw run identity, trusted issuer and verification disposition, and exact served_provider, served_model, served_model_version, and served_reasoning_effort. Those four served values form served_equivalence_stratum_v1; requested or self-asserted values never establish equivalence. Within each task class, an HTML-versus-Markdown comparison is eligible only when one exact centrally accepted stratum independently supplies at least ten otherwise eligible isolated reset observations for each format, five per form in each format. A missing, unresolved, rejected, mismatched, or held_model_unattested result is ineligible. Provider, model, version, or effort drift creates a separate observational stratum; no pooling, substitution, carried minimum, or cross-stratum comparison is permitted. The task-class comparison remains incomplete unless one stratum satisfies both format cells. This template consumes but does not establish or reinterpret central attestation trust or model-routing compliance.

Quality gate

  • Reject evidence without immutable tested identity, executor/tool identity, complete method envelope, or environment classification.
  • Reject summaries that omit immutable raw observation or silently rewrite a failing result; an unexecuted illustrative fixture is never evidence.
  • Reject verification used as stakeholder validation, or local evidence used as deployed/runtime truth.
  • Reject a pass when limitations, exceptions, non-actions, or unattested model service contradict the claimed disposition.
  • Historical evidence retains its original baseline identity and observation; hold only its applicability to a newer baseline until a linked applicability review or re-verification exists.
  • Mark current applicability stale when any tested requirement, either comparison artifact/baseline, revision, source hash, task material, answer key, scoring rule, participant/run configuration, tool/model configuration, or referenced evidence changes.
